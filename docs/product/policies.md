# 제품 정책

- 원본/근거: [MVP 정책](https://app.notion.com/p/3f91e7915bce8177a7fcf5b86d220de7), [기능 명세 초안](https://app.notion.com/p/3f91e7915bce81f89817c482350c29da), 3차 개발 요청 및 추천안 승인
- 확인일: 2026-10-16 (한국 시간)
- 문서 상태: 관련 원본 열람 완료 / 이번 범위 정책 확정

## 이번 단계 확정

- 이름은 앞뒤 공백을 제거하며 공백만 입력한 이름은 오류로 안내합니다. 미리보기의 ‘나의 다이어리’는 저장 기본 이름으로 쓰지 않습니다.
- 세 유형 모두 A4 첫 페이지 1개를 만듭니다. 날짜형은 생성 시 기기 현지의 오늘 날짜, 다른 유형은 날짜 없음입니다. [데이터 모델](../architecture/data-model.md)에 형식을 정의합니다.
- 로그인·서버 없이 로컬 저장하며 저장 성공 후 책장으로 이동합니다. 실패 시 입력과 화면을 유지합니다.
- 샘플은 별도 영역의 시연 데이터이며 사용자 데이터로 저장하지 않습니다.
- 읽기·편집·삭제·백업·동기화·로그인·결제는 구현하지 않습니다.

## 원본 확인 및 차이

기존 문서는 접근 실패로 비어 있었으나 이번에는 연결된 Notion 도구로 원본을 열람했습니다. 정책 원본은 마지막 확정 저장·충돌 보호 사본, 수동 비우기 휴지통, 자체 편집 백업의 새 다이어리 가져오기 기본값을 P0 정책으로 명시합니다. 이 정책들은 이번 단계에서 해당 기능을 구현한다는 뜻이 아닙니다.

원본 P0-2는 iPadOS 18 이상, 기능 초안 SAVE-01은 다이어리 저장 시 로그인을 제안합니다. 이번 요청에 따라 기존 최소 iPadOS 18.2와 기기 지원 설정을 유지하고 로그인 없이 저장합니다. 원본을 수정하거나 차이를 숨기지 않습니다. 날짜별 복수 페이지와 페이지별 크기 확장도 원본 기능 초안에 있으나 추가 UI는 후속 범위입니다.

원본의 상품·페이지 스키마는 설계 제안이며 초기 수·크기·최초 날짜의 구체 기본값은 미정이었습니다. 이번 대화에서 위 추천안을 승인받았습니다. 나머지 정책을 임의로 확정하지 않습니다.

## 4차 개발 — 읽기 정책

이전 단계에서 미구현이던 읽기와 로컬 책갈피를 추가합니다. 저장 날짜만 표시하고 빈 마지막 슬롯에 데이터를 만들지 않습니다. 회전 시 선택 UUID를 유지합니다. 이번 요청의 기본 한/두 페이지 규칙을 적용하며 다른 확정 정책은 기존 docs에서 확인되지 않았습니다.

상세 내용은 [읽기 명세](../design/reading-spec.md)와 [읽기 검증](../development/reading-verification.md)을 참고합니다.

## 5차 개발 — 기본 필기와 저장

이번 사용자 요청에 따라 고급 브러시·레이어·로그인·클라우드를 제외한 PencilKit 기본 필기와 로컬 자동 저장을 구현합니다. Notion EDT/SAVE 및 P0-1·2·3을 다시 열람했으며, 고급 브러시와 다기기 충돌 보호 정책 전체를 이번에 구현한 것은 아닙니다. 저장 성공 경계와 강제 종료 시 한계는 [필기 구조](../architecture/ink-editor.md)를 참고합니다.

## 6차 개발 — 사용자 승인 안전 정책

- 저장 충돌 시 확정본을 덮어쓰지 않고 보호 사본으로 보관합니다. 복구는 새 페이지 생성으로 제공합니다.
- 페이지는 복원 가능한 휴지통으로 이동하고 마지막 활성 페이지는 삭제할 수 없습니다. 수동 비우기의 영구 삭제 구현은 보류하며 자동 삭제하지 않습니다.
- 종이 밖 객체는 원래 좌표를 보존하고 종이 안에 겹치는 영역만 표시합니다.
- 페이지 관리·텍스트·사진은 이번 사용자 요청으로 구현 범위를 확장한 것이며 앞선 단계의 제외 목록은 당시 범위입니다.
- 이번 Notion 재접근은 403으로 실패했습니다. 위 규칙의 근거는 원본을 새로 읽은 결과가 아니라 6차 요청 및 승인입니다. 상세 동작은 [6차 구조](../architecture/page-decoration.md)를 참고합니다.
