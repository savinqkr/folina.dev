# 필기 데이터와 저장 구조

- 원본/근거: 5차 개발 요청 · [MVP 정책](https://app.notion.com/p/3f91e7915bce8177a7fcf5b86d220de7) · 저장소 구현
- 확인일: 2026-10-16 (한국 시간)
- 문서 상태: 기본 구현 / Apple SDK 실행 검증 필요

## 역할

- `PageInk`: 버전·엔진·문서/페이지 UUID·좌표 크기·원본 payload의 Codable 봉투.
- `PageInkStorage` / `PageInkStore`: 페이지별 원자적 파일 저장, actor에서 파일 I/O 직렬 실행.
- `InkEditorSession`: 드로잉·실행 취소 상태, 디바운스, 저장 순서와 오류 상태.
- `InkCanvas`: UIViewRepresentable과 PencilKit delegate 연결. 커스텀 도구 UI와 별개입니다.
- `DiaryEditorView`: 툴바·고정 페이지 확대·읽기 복귀와 앱 상태 처리.
- `PageInkOverlay`: 저장 원본을 읽어 표시용 이미지를 생성합니다. 읽기에서 편집 가능한 캔버스를 만들지 않습니다.

## 저장 형식과 위치

앱 샌드박스 `Application Support/FolinaInk/v1/<diary UUID>/<page UUID>.json`에 저장합니다. `version=1`, `engine=pencilkit`, `diaryID`, `pageID`, `width`, `height`, `payload`를 포함합니다. payload는 `PKDrawing.dataRepresentation()`의 편집 가능한 원본을 JSONEncoder가 Base64로 인코딩한 것입니다. 이미지가 정본이 아닙니다. 읽기 이미지는 파생 표시 데이터이며 디스크에 영구 저장하지 않습니다.

기존 SwiftData `FolinaLocal` 문서·페이지 모델·스키마·UUID는 변경하지 않습니다. 기존 다이어리는 필기 파일이 없으면 빈 필기입니다. 손상·알 수 없는 버전/엔진·ID 불일치는 빈 내용으로 간주하지 않고 읽기 오류를 표시합니다. 편집 불러오기 실패 시 덮어쓰기를 막습니다. DB와 필기는 별도 저장이므로 기존 책갈피·다이어리 JSON 전체를 획마다 다시 쓰지 않습니다. 필기 수정은 기존 문서 updatedAt을 변경하지 않습니다. 향후 전체 내보내기·삭제·백업은 반드시 이 sidecar 파일도 포함하도록 설계해야 합니다.

페이지별 JSON은 Base64 약 33% 증가와 드로잉 스냅샷 직렬화 비용이 있습니다. PKDrawing 직렬화는 MainActor에서, 파일 쓰기는 저장 actor에서 수행합니다. 현재 제한된 페이지 단위 구조이며 대용량 장시간 필기의 실기기 메모리·지연 수치는 측정하지 못했습니다. 장기적으로 바이너리 blob·별도 인덱스·캐시와 성능 측정을 검토합니다.

## 자동 저장 및 안전 경계

변경 후 400ms 디바운스를 적용하고 PencilKit 도구 사용 종료 시 즉시 저장합니다. 읽기 복귀 및 scenePhase 비활성/백그라운드에서도 저장합니다. 앱 상태 변경 저장에는 UIKit 백그라운드 작업 시간을 요청합니다. 저장 작업은 이전 요청 완료 뒤에 실행하여 오래된 스냅샷의 역순 덮어쓰기를 방지합니다. 저장 완료 revision이 현재 revision과 같을 때만 ‘저장됨’을 표시합니다. 실패 시 오류와 재시도, 메모리 원본을 유지하며 읽기 복귀를 막습니다.

파일은 `.atomic`으로 교체하여 쓰기 도중 중단될 때 기존 확정 파일을 보존합니다. 원자적 교체는 버전 기록이나 충돌 보호 사본 기능이 아닙니다. 현재 단일 앱 로컬 흐름이며 다기기 충돌 정책은 미구현입니다. OS 강제 종료·전원 손실·저장 공간 부족으로 **확정되지 않은 마지막 획/변경의 보존은 보장하지 않습니다**. 백그라운드 시간이 제공되지 않거나 만료되는 상황도 실제 iPad에서 검증해야 합니다. 저장 실패 후 사용자가 앱을 강제 종료하면 메모리 변경은 복구할 수 없습니다. 성공으로 표시한 데이터의 재실행 유지가 수용 기준입니다.

## 페이지 좌표

최초 편집 시 1mm=4 논리 단위로 페이지 크기를 정합니다(A4 세로 840×1188). 저장된 width/height를 이후 세션에서도 재사용합니다. SwiftUI는 캔버스와 속지를 같은 고정 프레임에서 동일 배율로 표시하며 화면 회전·창 크기·확대는 표시 배율만 바꿉니다. PKDrawing 좌표를 매번 스케일하여 저장하지 않습니다. 읽기는 저장 사각형 전체를 현재 종이에 맞춰 표시합니다. 페이지 크기 변경 UI는 없으며 향후 비율을 바꾸는 기능에서는 콘텐츠 유지/비례 변경 정책을 별도로 확정해야 합니다.

## 엔진 확장

PencilKit 펜/marker/벡터 지우개 및 세션 UndoManager를 사용합니다. 필압·기울기와 팜 리젝션은 선택한 도구·Pencil 기종·OS 제공 범위입니다. 손가락에는 필압을 가정하지 않습니다. 고급 텍스처·산포·커스텀 Metal·자유형 선택은 없습니다.

향후 커스텀 엔진은 별도 engine/version/payload를 추가하고 기존 PencilKit 원본을 유지해야 합니다. 모든 브러시가 PKDrawing으로 변환 가능하다고 가정하지 않습니다. 다중 레이어 도입 시 엔진별 콘텐츠·합성 순서·좌표·원본 무손실 보존 및 교차 엔진 실행 취소 경계를 설계합니다. 기존 알 수 없는 payload를 빈 드로잉으로 덮어쓰지 않습니다.
