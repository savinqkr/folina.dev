# 기술 결정 기록

- 원본/근거: 사용자 요청 및 저장소 직접 확인
- 확인일: 2026-10-15 (한국 시간, 외부 원본은 접근 시도일)
- 문서 상태: 책장 홈 구조 결정 기록

## 기록 원칙

중요한 기술적 결정은 근거와 함께 기록합니다. 기존 코드의 설정값을 이번에 승인된 기술 결정으로 취급하지 않습니다. 현재 상태는 [개요](overview.md)에 기록합니다.

각 결정에는 식별자, 제목, 날짜, 상태(제안/확정/대체), 문제와 제약, 검토한 대안, 선택과 근거, 영향과 단점, 원본 및 관련 문서, 확인 주체를 포함합니다. 제안과 미결정 항목은 확정으로 표시하지 않습니다. 대체 시 이전 결정을 삭제하지 않고 새 기록을 연결합니다.

## 결정 목록

최초 문서 구축에서는 앱의 아키텍처·저장 기술·최소 지원 버전을 새로 결정하지 않았습니다. 문서 관리 및 협업 규칙은 사용자 명시 지시에 따라 [문서 안내](../README.md)와 [AGENTS.md](../../AGENTS.md)에 기록합니다.

## ADR-001 — 책장 표시 모델과 샘플 분리

- 날짜: 2026-10-15 (한국 시간)
- 상태: 이번 범위 확정
- 확인 주체·근거: 사용자의 기본 구조·샘플 분리·외부 의존성 금지 요청과 저장소 확인
- 문제: 저장 방식이 미정인 초기 화면에 사용자 데이터 저장 구조를 임의로 확정하지 않아야 합니다.
- 대안: 화면 안에 샘플 직접 선언 / 외부 상태 관리 계층 도입 / 단순 표시 모델 주입
- 선택: `DiarySummary` 표시용 값과 `SampleDiaries`를 분리하고 `ContentView`에서 화면에 주입합니다. 제본·표지 색상은 별도 종류로 표현합니다.
- 근거: 이번 범위에 저장·편집이 없고 구조를 확장하기 쉽습니다. 기존 Xcode 동기화 폴더와 SwiftUI만 사용합니다.
- 영향·단점: 영구 저장·사용자 목록·탐색은 후속 작업입니다. 표시 모델을 그대로 저장 스키마로 간주하지 않습니다.
- 관련 문서: [아키텍처](overview.md), [화면 명세](../design/screen-spec.md)

## ADR-002 — 생성 초안의 단일 상태와 SwiftUI 미리보기

- 날짜: 2026-10-16 (한국 시간)
- 상태: 이번 범위 확정
- 확인 주체·근거: 사용자의 2차 개발 요청, 비율만 적용 및 기본형·식물 창 장식 선택 답변
- 문제: 옵션·표지·속지 미리보기가 같은 선택을 표시하고 외형 변경이 기록 방식을 바꾸지 않아야 합니다. 저장 방식·실제 용지 규격은 미정입니다.
- 대안: 각 미리보기에 별도 상태 보관 / 외부 상태 라이브러리 / 화면 소유 값 타입과 Binding
- 선택·근거: 화면이 `DiaryDraft` 하나를 소유하고 재사용 옵션 컴포넌트에 필드별 Binding을 전달합니다. 미리보기는 같은 값을 읽습니다. 외부 의존성 없이 갱신 일관성을 유지합니다.
- 영향·단점: 뒤로 가면 초안을 폐기합니다. 실제 저장·책장 등록·날짜형 페이지 생성은 후속 구현입니다. 미리보기 비율은 실제 용지 규격이 아닙니다.
- 렌더링: SwiftUI 도형·Canvas 및 기존 금속 링·표지 장식을 재사용합니다. Figma 링 에셋 다운로드 403과 사용자 기본 그래픽 활용 요청에 따른 것으로 원본 에셋과 픽셀 일치를 보장하지 않습니다.
- 관련 문서: [생성 화면 명세](../design/creation-spec.md), [데이터 모델](data-model.md)

## ADR-003 — SwiftData 문서 저장과 생성 완료 경계

- 날짜: 2026-10-16 (한국 시간)
- 상태: 이번 범위 확정
- 확인 주체·근거: 3차 개발 요청, 초기 1페이지·A4·현지 오늘 날짜 추천안 사용자 승인
- 문제: 외부 라이브러리 없이 문서·초기 페이지를 안전하게 저장하고 실패를 성공으로 표시하지 않아야 합니다.
- 대안: 원자적 JSON 파일 저장 / Core Data / SwiftData의 문서 행. 기존 사용자 저장소는 없습니다.
- 선택: iPadOS 18.2에서 제공되는 SwiftData, 고유 문서 UUID + 버전 + Codable 문서 데이터. 기존 DiaryDraft 옵션을 재사용하고 표시 모델은 저장하지 않습니다. 별도 ModelContext, autosave 해제, 명시적 save/rollback으로 생성 경계를 만듭니다.
- 근거: Apple 기본 트랜잭션 저장과 향후 조회 확장이 가능하고 앱에 외부 의존성·프로젝트 설정 변경이 필요 없습니다. JSON 파일 직접 관리보다 파일 충돌/원자성 처리를 줄입니다. Core Data의 수동 설정은 현 단계에 과도합니다.
- 영향·단점: 페이지별 검색은 현재 문서 디코딩이 필요합니다. 대용량 편집 시 문서 행의 JSON 대신 페이지·미디어 별도 저장을 재검토해야 합니다. 버전 변경 시 명시적인 마이그레이션이 필요합니다. SwiftData는 Mac/Xcode에서 검증해야 합니다.
- 상태: 로딩 실패 시 기존 데이터 유지·생성 차단·재시도, 저장 실패 시 rollback·입력 유지·오류 안내. 컨트롤러의 isSaving/hasCreated로 중복 생성 요청을 차단합니다. 샘플은 별도 접힌 영역에서만 표시합니다.
- 범위 차이: Notion SAVE-01 로그인 요구와 P0-2 iPadOS 18 이상은 이번 요청의 로그인 없는 로컬 저장 및 기존 최소 18.2 유지와 구분합니다. 원본은 수정하지 않았습니다.
- 관련 문서: [데이터 모델](data-model.md), [제품 정책](../product/policies.md)

## ADR-004 — UUID 기반 읽기와 선택적 책갈피 확장

- 날짜: 2026-10-16 (한국 시간)
- 상태: 이번 범위 구현 결정 / Mac 검증 필요
- 확인 주체·근거: 4차 개발 사용자 요청, Figma 27:125 및 기존 코드 확인
- 문제: 회전으로 읽던 페이지가 바뀌지 않고 기존 저장 데이터를 유지하며 책갈피를 영구 저장해야 합니다.
- 대안: 인덱스만 보관 / 별도 파일·UserDefaults의 책갈피 / 기존 문서에 선택적 UUID 집합 추가
- 선택·근거: 선택 페이지 UUID를 화면 상태로 보관하고 레이아웃마다 그 페이지가 포함된 펼침을 계산합니다. 기존 배열 순서는 유지합니다. 책갈피는 문서 JSON의 선택적 집합으로 추가해 기존 행 스키마와 저장 트랜잭션을 재사용합니다.
- 영향·단점: 이전 JSON은 변경 없이 읽고 DB를 초기화하지 않습니다. 구버전 재저장 시 신규 필드 보존은 보장하지 않습니다. 페이지별 조회와 대용량 편집 구조는 후속 설계 대상입니다. 마지막 읽던 위치의 앱 재실행 복원은 이번 범위 밖입니다.
- UI: 760pt 이상 가로 창은 펼침, 나머지는 한 페이지. 스와이프/목록/저장 조작은 종이 외형 컴포넌트와 분리합니다. 애니메이션은 이동/페이드이며 외부 물리 엔진을 사용하지 않습니다.
- 관련 문서: [읽기 명세](../design/reading-spec.md), [데이터 모델](data-model.md), [검증](../development/reading-verification.md)

## ADR-005 — PencilKit 원본과 페이지별 파일 저장

- 상태/확인일: 5차 요청에 따라 채택, 2026-10-16 / Mac 검증 필요
- 결정: 기본 필기는 PencilKit으로 제공하고 engine/version/좌표를 가진 페이지별 원본을 actor에서 원자적으로 저장합니다.
- 대안: 이미지 단독 저장은 재편집을 잃고, 문서 JSON 내 삽입은 획마다 전체 문서 재기록 비용이 커 제외합니다. 신규 Metal 엔진은 이번 범위 밖입니다.
- 영향: 기존 SwiftData 스키마를 유지하지만 향후 삭제·백업 시 sidecar도 처리해야 합니다. Base64 비용과 실제 Pencil 성능 검증이 필요합니다. [상세 설계](ink-editor.md)를 참고합니다.
