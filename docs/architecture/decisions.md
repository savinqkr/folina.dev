# 기술 결정 기록

- 원본/근거: 사용자 요청 및 저장소 직접 확인
- 확인일: 2026-10-15 (한국 시간, 외부 원본은 접근 시도일)
- 문서 상태: 책장 홈 구조 결정 기록

## 기록 원칙

중요한 기술적 결정은 근거와 함께 기록합니다. 기존 코드의 설정값을 이번에 승인된 기술 결정으로 취급하지 않습니다. 현재 상태는 [개요](overview.md)에 기록합니다.

각 결정에는 식별자, 제목, 날짜, 상태(제안/확정/대체), 문제와 제약, 검토한 대안, 선택과 근거, 영향과 단점, 원본 및 관련 문서, 확인 주체를 포함합니다. 제안과 미결정 항목은 확정으로 표시하지 않습니다. 대체 시 이전 결정을 삭제하지 않고 새 기록을 연결합니다.

## 결정 목록

최초 문서 구축에서는 앱의 아키텍처·저장 기술·최소 지원 버전을 새로 결정하지 않았습니다. 문서 관리 및 협업 규칙은 사용자 명시 지시에 따라 [문서 안내](../README.md)와 [AGENTS.md](../../AGENTS.md)에 기록합니다.

## ADR-001 — 책장 표시 모델과 샘플 분리

- 날짜: 2026-10-15 (한국 시간)
- 상태: 이번 범위 확정
- 확인 주체·근거: 사용자의 기본 구조·샘플 분리·외부 의존성 금지 요청과 저장소 확인
- 문제: 저장 방식이 미정인 초기 화면에 사용자 데이터 저장 구조를 임의로 확정하지 않아야 합니다.
- 대안: 화면 안에 샘플 직접 선언 / 외부 상태 관리 계층 도입 / 단순 표시 모델 주입
- 선택: `DiarySummary` 표시용 값과 `SampleDiaries`를 분리하고 `ContentView`에서 화면에 주입합니다. 제본·표지 색상은 별도 종류로 표현합니다.
- 근거: 이번 범위에 저장·편집이 없고 구조를 확장하기 쉽습니다. 기존 Xcode 동기화 폴더와 SwiftUI만 사용합니다.
- 영향·단점: 영구 저장·사용자 목록·탐색은 후속 작업입니다. 표시 모델을 그대로 저장 스키마로 간주하지 않습니다.
- 관련 문서: [아키텍처](overview.md), [화면 명세](../design/screen-spec.md)
