# 데이터 모델

- 원본/근거: [상품 및 데이터 모델](https://app.notion.com/p/3f91e7915bce813085e3fe2b6ae1f8a0)
- 확인일: 2026-10-15 (한국 시간, 외부 원본은 접근 시도일)
- 문서 상태: 자료 확인 필요

엔터티, 속성, 식별자, 관계, 상품 구조, 저장·동기화 방식은 원본 자료 확인 필요입니다. 사용자가 원본에 지정한 모델을 확인하지 않고 임의의 스키마를 작성하지 않습니다.

현재 책장 표시용 `DiarySummary` 값과 제본·표지 종류를 추가했습니다. 이는 영구 저장 스키마가 아니며 사용자 데이터 저장 구현은 없습니다. 이는 원본에 모델이 없다는 뜻은 아닙니다. 확정 시 [제품 정책](../product/policies.md)과 연결하고 기술 선택은 [결정 기록](decisions.md)에 남깁니다.

## 2차 개발의 화면 초안 — 2026-10-16

`DiaryDraft`는 이번 사용자 요청으로 확정한 화면 상태입니다. `DiaryKind`, 기존 `DiaryBinding`·`DiaryCoverTone`, `CreationCoverStyle`, `DiaryPaper`, `DiaryOrientation`을 각각 별도로 관리합니다. 유형을 바꿔도 외형·속지 선택을 초기화하지 않습니다. 새 제본을 추가할 때는 `DiaryBinding`·표시 제목·렌더러를 확장하고 `creationOptions`에 노출합니다. 불렛저널은 제본 옵션에 없습니다.

초안은 값 타입이며 Codable을 지원하지만 현재 파일·DB·UserDefaults에 쓰지 않습니다. ID·페이지 개수·물리 용지 크기·날짜 범위는 정의하지 않았습니다. 향후 확정 정책에 따라 저장 모델과 매핑하고 저장 성공 후에만 책장 목록을 갱신해야 합니다.
