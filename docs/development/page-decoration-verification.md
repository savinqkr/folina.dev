# 6차 개발 검증

- 원본/근거: 6차 개발 요청 및 현재 구현
- 확인일: 2026-10-16 (한국 시간)
- 문서 상태: Linux 정적 검사 / Apple SDK 검증 미실행

## 작성한 자동 테스트

`PageManagementTests.swift`와 `PageDecorationTests.swift`에 다음 시나리오를 추가했습니다. 기존 `PageInkTests.swift`의 저장 업데이트와 테스트 저장소에도 기대값 비교를 적용했습니다.

- 기존 JSON의 휴지통 필드 누락 호환, 추가·휴지통·재로딩·원래 위치/책갈피 복원
- 마지막 페이지 삭제 거부, 잘못된 순열·중복 ID 작업 거부, 순서 변경 후 페이지별 속지/책갈피 UUID 유지
- 실제 SwiftData 디스크 재로딩, 오래된 문서의 페이지 작업 거부
- 한글·줄바꿈 원본 문자열, 음수/종이 밖 좌표, 크기·회전·프레임·색상 디스크 왕복
- 사진 UUID 파일 저장/재로딩, 원본 바이트와 공유 참조 유지, 복제 객체·필기 UUID 및 파일 분리
- 필기/객체 충돌 시 확정본 유지와 영속 보호 사본, 새 페이지 복구
- 누락된 사진·손상 파일 덮어쓰기 차단, 꾸미기 저장 실패 시 메모리 유지·재시도

Apple SDK를 사용할 수 없어 **위 테스트와 기존 전체 테스트는 실행하지 않았습니다**. 문자열 저장 테스트는 한글 IME의 조합 입력 동작 검증을 대체하지 않습니다. 사진 저장 fixture는 파일 보존 검증용이며 PhotosPicker 권한/실제 사진 디코딩 검증을 대체하지 않습니다.

## Linux에서 실제 수행

- Swift tree-sitter 구문 검사. Swift 타입 검사·앱 빌드가 아닙니다.
- `git diff --check`, 문서 상대 링크/앵커 검사.
- 기존 Xcode 프로젝트/최소 OS/기기 지원 설정 변경 없음 확인.
- GitHub API에서 5차 PR #6의 main 병합 확인.
- Notion 3개·Figma 2개 재접근 실패(403). 최신 원본 대조 미실행.

## Mac Xcode 및 iPad에서 확인할 순서

1. 기존 사용자 데이터의 복사본을 준비합니다. Xcode에서 FOLINA 스킴과 iPadOS 18.2 이상 시뮬레이터를 선택해 빌드·전체 단위/UI 테스트를 실행합니다. 구버전 문서·책갈피·PKDrawing을 열고 수정 전 데이터가 그대로인지 확인합니다.
2. 날짜형/자유형/스크랩북에서 페이지 추가 후 선택 위치·기본 속지·날짜를 확인하고 앱 재실행 후 유지되는지 확인합니다.
3. 서로 다른 필기·한글 텍스트·사진이 있는 페이지를 복제한 뒤 각각 수정합니다. 원본·복제본 간 혼입이 없고 사진 원본 공유가 안전한지 확인합니다.
4. 목록의 이동 핸들을 여러 번 드래그해 순서를 바꾸고 재실행합니다. 선택 UUID·책갈피·필기·사진 연결이 유지되는지 확인합니다.
5. 삭제 확인 취소/승인, 마지막 페이지 삭제 제한, 휴지통 재실행 유지 및 복원 위치·책갈피·사진/필기 보존을 확인합니다.
6. 텍스트 추가 → 속성 TextEditor에서 한글 조합/받침 수정/줄바꿈 → 글자 크기·색상 변경 → 저장·재열기. 키보드 표시 중 좁은 창과 큰 글자 설정에서 도구 접근을 확인합니다.
7. PhotosPicker 취소/선택/네트워크 원본 다운로드 실패를 확인합니다. 실제 가로·세로·HEIC·JPEG·PNG 사진을 삽입하고, 원본 보관함 사진을 삭제한 뒤에도 재실행 시 표시되는지 확인합니다.
8. 텍스트·사진을 이동·핸들 크기 조절·두 손가락 확대/회전하고 일반·폴라로이드·코너를 전환합니다. 프레임 변경이 원본 바이트를 바꾸지 않는지 확인합니다. 사진 비율과 이동/회전 제스처의 우선순위를 실제 iPad에서 확인합니다.
9. 펜 모드에서 객체가 움직이지 않고, 선택 모드에서 필기가 생기지 않는지 Pencil·손가락으로 확인합니다. 확대 페이지 스크롤과 객체 드래그가 충돌하지 않는지 확인합니다.
10. 종이 모서리 기준으로 읽기·편집 좌표를 비교하고 회전·Split View·Stage Manager·100–300% 확대 후에도 원본 좌표가 유지되는지 확인합니다. 일부/전체가 종이 밖인 객체의 clip, 목록 선택과 가운데 이동을 확인합니다.
11. 저장소에 충돌을 주입하고 확정 파일과 보호 사본 모두 보존되는지 확인합니다. 페이지 관리에서 종류별 사본을 새 페이지로 복구하고 원본·사본을 유지하는지 확인합니다. 문서 작업 충돌 시 재로딩 뒤 재시도합니다.
12. 사진 저장/JSON 저장/페이지 DB 확정 각각의 디스크 부족·쓰기 실패를 주입합니다. 기존 데이터 유지, 성공 표시 차단, 메모리 내용 유지 및 재시도를 확인합니다. 강제 종료는 확정 전과 확정 후를 구분합니다.
13. 여러 대형 사진과 장시간 필기의 메모리·저장 지연을 측정하고 실제 스크린샷을 PR에 첨부합니다. 이번 Linux 작업에서는 스크린샷을 촬영하지 못했습니다.
