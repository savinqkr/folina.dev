## 확정 계획

원본의 개발 단계, 우선순위와 일정은 아직 확인하지 못했습니다. 확정된 출시일이나 기능별 일정을 기재하지 않습니다.

## 제안사항 — 준비 순서

1. 원본 자료 접근을 확보하고 요구사항·디자인을 확인합니다.
2. 모호한 사항을 질문하고 MVP 범위 및 수용 기준을 확정합니다.
3. Mac/Xcode에서 기존 앱 빌드·실행을 확인합니다.
4. 합의된 범위로 작업을 나누고 기능별 구현·검증·문서 갱신을 PR로 검토합니다.

이 순서는 준비 절차 제안이며 원본 로드맵을 대체하지 않습니다. 구체적인 미확인 항목은 [백로그](backlog.md)에 모읍니다.

## 이번 구현과 후속 확인

책장 홈은 [이번 기능 범위](../product/feature-spec.md)로 작성했습니다. 출시 일정이나 후속 기능 순서를 새로 확정하지 않았습니다. Mac에서 아래 절차로 실제 빌드·검증 후 다음 기능을 결정합니다.

1. Xcode 16.2 이상에서 `FOLINA.xcodeproj`를 엽니다.
2. `FOLINA` 스킴과 iPadOS 18.2 이상 iPad 시뮬레이터를 선택합니다.
3. Product → Build(⌘B), Run(⌘R)으로 책장 홈을 확인합니다.
4. Product → Test(⌘U)로 기존 테스트 및 `BookshelfUITests`를 실행합니다.
5. 가로·세로 회전, 좁은 Split View 창, 큰 글자 크기에서 표지·제목·생성 버튼을 확인합니다.
6. 샘플 7개와 제본 외형을 확인하고, 생성 버튼이 안내만 표시하는지 확인합니다. 앱을 다시 실행해도 사용자 데이터가 만들어지지 않아야 합니다.

Linux에서 위 절차를 실행하지 못했으며 빌드 성공을 보장하지 않습니다. 실제 화면 캡처와 Figma 비교는 Mac 검증 후 PR에 첨부해야 합니다.
