- 원본/근거: 3차 개발 요청 및 현재 구현
- 확인일: 2026-10-16 (한국 시간)
- 문서 상태: Mac 실행 필요 / Linux에서 미실행

## 자동 테스트

`DiaryStorageTests`는 생성·다중 문서·모든 설정 보존·새 디스크 컨테이너 재로딩·현지 날짜·빈 이름·동시/완료 후 중복 요청·저장 실패 후 재시도·로딩 실패 후 재시도·손상/미지원 버전 보존을 검증하도록 작성했습니다. 저장 실패는 주입한 테스트 저장소로 시뮬레이션하며 실제 기기 용량 부족을 재현한 테스트는 아닙니다. `BookshelfUITests`는 생성 후 종료·재실행·정보 화면과 기존 옵션/취소 흐름을 검증합니다.

앱 테스트에는 외부 라이브러리를 추가하지 않았습니다. SwiftData 매크로·컴파일·동작은 Linux 구문 검사만으로 검증할 수 없습니다.

## Mac 수동 검증 순서

1. Xcode 16.2 이상에서 FOLINA.xcodeproj를 열고 FOLINA 스킴·iPadOS 18.2 이상 iPad 시뮬레이터를 선택합니다. Build, Test를 수행하고 결과를 PR에 기록합니다.
2. 별도 테스트 설치에서 첫 실행 시 빈 책장, 생성 버튼 활성화, 샘플 접힌 영역을 확인합니다. 실제 사용자 데이터가 있는 앱은 삭제/초기화하지 않습니다.
3. 공백 이름으로 생성해 오류·입력 유지·책장 미등록을 확인합니다.
4. 날짜형·자유 기록형·스크랩북을 다른 이름·제본·대표/사용자 색상·표지·속지·방향으로 각각 생성합니다. 연속 탭에도 1개만 생기는지 확인합니다.
5. 저장 완료 후 책장 복귀·새 문서 맨 앞 표시·색상/제본/이름을 확인하고 각 문서에서 정보 화면의 A4 크기·1페이지·날짜를 확인합니다.
6. 앱을 완전히 종료 후 다시 실행해 여러 문서와 각 설정이 유지되는지 확인합니다. 샘플은 저장 목록에 포함되지 않아야 합니다.
7. 테스트 저장소의 실패 주입 단위 테스트로 저장 실패 시 미등록·오류·재시도, 로딩 실패 시 생성 차단·재시도·원본 보존을 확인합니다. 파일 손상 실험은 복사한 테스트 저장소에서만 합니다.
8. 가로·세로·Split View·큰 글자·VoiceOver를 확인합니다. 생성 중 뒤로 가기/옵션/버튼이 잠기고 저장 오류 후 다시 사용할 수 있어야 합니다.

실제 디바이스 용량 부족·프로세스 강제 종료 중 트랜잭션·OS 파일 보호·장기간 데이터 증가 테스트는 아직 수행하지 않았습니다. 저장 완료 전 강제 종료된 초안의 복구는 이번 범위가 아닙니다.
